### Operating limits

- A feed check confirms that a source returned usable data. The counts describe matching records before cross-source deduplication. CVE and EPSS enrichment still has its own lookup limits and may be unavailable after a complete collection. The dashboard marks collections over 90 minutes old as stale and preserves the incomplete-coverage label when both apply.
- Public collection requests use short connect and read timeouts, capped streamed bodies and scoped HTTPS redirects. A slow response that keeps the socket active can exceed the elapsed target before the next chunk arrives. The hosted collection job also has a 15-minute ceiling. [Requests streaming responses](https://requests.readthedocs.io/en/latest/user/quickstart/#raw-response-content)
- GitHub may delay or drop scheduled triggers. The workflow catches up only within the active briefing slot and searches the latest 20 completed runs for a validated dataset. It can fall back to the checked-in archive after an extended failure. A failed validation blocks publication. Local writes replace individual files atomically, and the staging validator rejects inconsistent exports after an interrupted write. [GitHub Actions scheduling and concurrency](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onschedule)
- Webhook responses can leave delivery uncertain, including a read timeout, HTTP 5xx, HTTP 408 or a crash after claiming a delivery. These rows remain held in private state for reconciliation. Generic incoming webhooks cannot guarantee provider-side exactly-once delivery. GitHub Actions webhooks are disabled. Keep the outbox on persistent private storage and preserve it when restoring service. Collection can continue when local notification storage fails, so alerts from those runs may be missed.
